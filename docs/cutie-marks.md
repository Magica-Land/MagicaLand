# 自绘可爱标志

可爱标志使用两侧大腿根外侧的整张面，固定为 12×12 像素。不调整模型、骨骼、UV 或原始贴图。

## 界面

捏脸顶栏新增“可爱标志”：提供颜色选择、画笔、橡皮、吸色、撤销/重做和水平镜像。一次拖画算一条历史，最多保留 64 条，越界后不会跨空白连线。左右分别编辑或共用；重新共用前需要确认，撤销还能恢复覆盖前两侧。选择左右时自动预览对应大腿，关闭自动聚焦后不接管镜头。

预览上方的预设名字现为下拉菜单，标记当前选择和未保存草稿。右侧“+”新建：输入名字并确认后才切换到新草稿；“−”删除：二次确认中显示当前完整名称，最后一个预设禁止删除。快捷操作确认或取消后回到原编辑分类；取消不会创建、删除或切换预设。菜单展开时点击外面仅收起，不会穿透触发快捷按钮。

下拉底部“管理预设…”继续提供新建、复制、改名、删除。原来的独立顶栏预设分类撤去，管理功能没有删除。切换保留各预设草稿和独立绘图历史，关闭编辑会话才统一释放；新建/删除仍只改本次草稿，保存才写入文件并仅应用当前预设，放弃编辑可恢复删除。

## 数据与预设

`ModelConfig` 的 `cutieMarkLeft`、`cutieMarkRight` 保存固定 RGBA 字节的 Base64；`cutieMarkLinked` 默认开启。联动时只存左侧数据，右侧字段为空；解锁复制当前共用图，重新锁定采用编辑中的那一侧。字符串不可变，读取画布每次返回新数组，因此预设复制与左右独立编辑不会共享可变像素。

`CutieMarkData` 限定 144 像素、576 字节、768 个 Base64 字符。只允许完全透明或不透明，透明像素的 RGB 归零，全透明图存为空字符串。没有图片文件、网址、压缩解码或任意尺寸入口。旧预设没有这些字段时保持空白。

画笔操作只修改现有捏脸草稿；取消恢复旧外观，保存后才写预设并同步多人。仍使用现有模型消息与 16384 字符上限，两张图最多占 1536 字符；不逐笔发送、不提高发送频率。服务端转发前与接收客户端都验证字段类型、编码长度、像素透明度与规范形式。服务器仅保留在线外观，不新增远程图案磁盘缓存。

## 显示

在身体调色完成后的动态纹理上合成图案，只交给对应大腿骨骼：

- `LHindLeg`：256² 图集 `[88,54]` 到 `[100,66]`，右、下边界不包含。
- `RHindLeg`：`[56,78]` 到 `[68,90]`，右、下边界不包含。

已用实际 GeckoLib 烘焙结果校验，每块只覆盖该骨骼的一张完整外侧面；其他骨骼仍使用没有标志的身体纹理。图案 RGB 不被身体颜色或自定义身体阴影改色，只乘原始身体图的稳定灰度明暗，再照常接受场景光照。橡皮恢复调色后的身体像素，不把身体擦透明。旧式乘色模式先烘焙原身体乘色，再覆盖图案，避免图案二次染色。

没有额外面片或半透明层，因此不引入 Z-fighting、深度排序或身体透明问题。整数倍的方形资源包按最近邻放大；不符合原图集比例的资源包不绘制标志。

正式/远程纹理按颜色、侧别和图案缓存，沿用数量与显存预算、资源重载和离线清理。编辑中的当前预设只使用两个可复用草稿纹理槽，每次笔画更新原纹理，暂停菜单中也不会按笔画累积注册新纹理。草稿纹理不修改已应用或其他玩家的缓存，退出编辑后清理。

## 验证

`tests/cutiemark/CutieMarkDataTest.java` 覆盖编解码、透明度、坏输入、镜像、左右联动、预设复制和消息校验接入。

`CutieMarkTextureTest.java` 检查真实 base.png、真实烘焙 UV、两面范围、像素比例、明暗/颜色/透明度，以及纹理隔离和预算守卫。

`CutieMarkDraftTest.java` 使用现有测试存档隔离设施，覆盖未保存不落盘不联网、取消、保存重读及复制后独立编辑。以上为无游戏窗口测试；实际画笔交互与游戏内外观仍需验收。
