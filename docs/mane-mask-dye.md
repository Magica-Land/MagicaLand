# 01 全区域遮罩分色

2026-09-08：01 前发、后发、尾巴各 6 区，共 18 个独立色槽。经作者确认并入正式源码；未重新打包发布 JAR。

## 开发者速览

核心是把“纹理明暗”和“这一块染什么颜色”拆开。原 `mane.png` 继续保存灰度纹理和手绘明暗；`stripe01.json` 按 UV 像素指定色区编号。渲染时读色区，找到玩家选择的颜色，再套用原灰度对应的色阶。因此换挑染不需要给模型叠一层几何，也不会丢掉发丝纹理。

| 文件/模块 | 职责 |
| --- | --- |
| `mane_dyes/stripe01.json` | 只描述 01 的色区形状，1–6 是编号，不是 RGB 或阴影强度 |
| `ManeDyeMask` | 校验并展开 JSON 遮罩，兼容旧版编号，按纹理尺寸取样 |
| `ModelConfig` | 保存每部件的 6 色；null 表示锁定跟随该部件主色，并迁移旧配置 |
| `ManeDye` + `ManePalette` / `BodyColorRamp` | 解析主色联动和色区锁，为独立颜色计算阴影/高光，保持原 alpha |
| `ManeTintTextures` | 合成并缓存动态纹理；同一配色复用结果，资源重载/退出时回收 |
| `ManePage` / `PonyRenderer` | 折叠式颜色控件；选择部件纹理并跳过旧挑染覆盖骨骼 |

例如后发 4 区设粉色、5 区设紫色，其余色槽为 null：4、5 区用自己的色阶，其余完整继承后发主色及其手动/自动明暗。前后发和尾巴各有自己的数组，颜色保存和联机同步仍走现有整对象 JSON，不需要新增服务端消息类型。

维护时主要注意：

- 改形状改遮罩，改质感改基础贴图；不要用明暗像素值反推色区，否则阴影会被误分成挑染。
- 改 01 UV 后必须同步遮罩。新增发型时需要配套遮罩、资源选择和编号支持逻辑，不能只改 JSON 的 `style` 字段。
- 锁定色区必须继承完整色阶，而不只是同一个主色 RGB，否则主色手动调阴影时仍会露出分界。
- `Resources` 中的贴图/模型与 `src/main/resources` 中的运行时版本要一起维护；Blockbench 不会执行 Java 调色代码，玩家分色不应烘焙回基础贴图。

独立逻辑测试：`./tests/mane/run-dye-tests.ps1 -GsonJar '本机现有 gson.jar 的绝对路径'`。需要 JDK 17+，仅编译测试到临时目录，不运行 Gradle。

## 使用

捏马 → 编辑角色 → 鬃毛与尾巴 → 遮罩分区调色。开启后，在对应部件主色下展开“前发分色 / 后发分色 / 尾巴分色”。只对编号 01 生效，混搭其他编号不串染。

- 每区锁定时跟随本部件主色和完整高光/阴影；解锁保留当时颜色，然后可以独立调整。
- 相邻的 4、5 区可设置为粉、紫，其余区跟随主色，即可手动搭配双带挑染。全部区域解锁后可做多色搭配。
- 每个部件单独保存 6 色，不强制前发、后发、尾巴使用同一套色槽。部件主色之间原有联动锁保留；色区锁表示跟随本部件主色，而非跟随另一个部件的同编号色区。
- “全部色区跟随本部件主色”将当前部件的 6 色重新锁定；关闭总开关只停用分色，不清空配色。
- 不同于主色的独立色区自动计算明暗；本轮未增加逐色区的阴影/高光手动编辑。与主色相同的色区复用主色完整色阶，手动阴影时也不留分区边线。

默认不开启分区调色。原有挑染配置迁移时，前发/尾巴的旧挑染色放入 4、5 两区；后发 4 区继承主挑染色、5 区继承副挑染色。其余区域默认跟随主色，因此不会默认变成六色彩虹。

## 形状和纹理

基础贴图仍提供已确认的纹理和三阶明暗；JSON 遮罩只存色区编号。本次六区分色未再改变已确认的模型、UV、动画、Blockbench 工程或 TS 原稿，也没有增加覆盖模型或提高分辨率。本提交同时包含此前已确认的 01 UV/纹理维修及其源文件与运行时副本。

后发色带参考作者 `Resources/Textures/TS.png`，使用白模化前提交 `3fbe96f39e76c7dd717a7cb00ecb9b9aafdcfbb9` 中的旧 UV 恢复位置。为满足本次上移和铺满分区的要求，将原稿粉/紫像素的对应位置拟合为连续三维分区坐标，上移 1.25 个模型单位，再延展到相邻发片和厚度面。它不是上一轮原稿逐像素遮罩的原位复制，也不再局限于原稿中有挑染的少数面。

拟合的源 UV 坐标误差 RMS 约 0.211 逻辑 UV 单位，低于半个原图物理像素。按当前像素网格栅格化，因此斜边保留像素台阶，不做平滑或提高贴图分辨率。前发和尾巴的 4、5 区合并后，严格等于先前正式挑染遮罩的覆盖范围；新增其他区域补满原先只有主色的部分。

全套 01 共 246 个面、9812 个面内纹理像素均有唯一分区，含 UV 边缘 padding 共 17092 像素。其余发型不共用本轮新增的 01 UV 区域。

## 数据与兼容

`assets/magicaland/mane_dyes/stripe01.json` 使用 version 3、256×256 像素坐标。每个 region 包含 `part`、`channel`、`runs`。`part` 为 FRONT / BACK / TAIL；`channel` 为 1–6；每条 run 为 `[y,x0,x1]`，终点 x1 不包含。遮罩外为主色。预设名仍为 `stripe01`，运行时只适用编号 01。

读取时限制 18 区、8192 条 run、1024×1024 尺寸和 256 KiB 资源大小；拒绝非法坐标、重复区域和同部件内重叠。仍支持旧 version 1 / 2 资源，旧通道 1 / 2 分别规范化为新色区 4 / 5。旧版客户端不能读取 version 3，联机双方应使用同版本。

新增 `frontManeDyeColors`、`backManeDyeColors`、`tailDyeColors` 三个长度为 6 的数组，null 色槽表示跟随主色。旧 `maneDyeColor` / `maneDyeAccentColor` 仅用于缺少数组时的一次迁移；有数组后以数组为准。非法色值回退为跟随主色，过长/过短数组规范化为 6 项。

保存、复制、联机继续使用现有 JSON 通道，不修改服务端转发协议。缓存键使用不可变的实际部件色阶列表，修改后发不会误改前发/尾巴，关闭分色时色槽不影响缓存。保留原 128 项 / 64 MiB 缓存限制和资源重载清理、故障后普通发色回退。

旧 `Style01FrontManeHighlight` 仍在源工程中保留回退资料，但游戏渲染跳过它。Blockbench 不执行玩家调色代码；不要把玩家色区配色涂进灰度源图。
