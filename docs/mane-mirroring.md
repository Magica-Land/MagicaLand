# 鬃毛与尾巴左右镜像

前发、后发、尾巴各有独立的「左右镜像」开关，位于对应部件的款式池上方。切换只影响当前部件，不增加编号，也不改变该部件的颜色联动状态。主预览与款式缩略图同时显示对应方向；缩略图仍使用固定示例颜色。

`ModelConfig.frontManeMirrored`、`backManeMirrored`、`tailMirrored` 默认为 `false`，旧预设保持原状。三个开关随现有预设保存/复制与模型消息传输；编辑时其他玩家仍只看见已应用版本，保存后才同步。无需新消息或额外网络更新。

## 渲染处理

在 `FrontMane`、`BackMane`、`Tail` 三个组件根的父空间做 X 反射。根的连接轴均为 X=0，因此连接位置保持不变；非居中的子骨骼、整个尾巴及其当前动画姿态一起翻转，而不是分别围绕每一小段反转。头部、身体、眼睛及其他部件不受影响。

不修改共享骨骼、动画、几何、UV、PNG 或挑染遮罩。UV 随原顶点移动，所以手绘纹理、高光细节与挑染都跟随造型翻转；镜像不会再额外翻一次贴图，也不会生成重复调色纹理。

没有直接使用 `MatrixStack.scale(-1,1,1)`。Minecraft 1.20.1 的该方法包含法线矩阵的负行列式归一化，不能直接用于这里的单轴反射。实现分别反射位置矩阵和法线矩阵，并反向输出镜像子树的顶点绕序，保留正常背面剔除、场景光照与材质参数。作用域退出或绘制异常时恢复父矩阵与镜像标记，不影响同帧其他玩家或预览。

自动取景使用相同的静止组件反射；取景缓存与缩略图缓存均包含镜像标记，因此非对称发型翻到另一侧后能重新正确取景。镜像不把动画姿势写入静态取景模型。

## 验证与注意事项

- `tests/mane/ManeMirrorTest.java`：实际模型的全部三个组件子树、五组关节/父级姿势，检查位置、法线、绕序、UV、颜色/光照参数，以及共享模型与矩阵恢复。
- `tests/gui/ManeMirrorPreviewTest.java`：逐个现有发型和尾巴检查静止取景、镜像缓存、缩略图方向与固定素体颜色。
- `tests/mane/ManeMirrorDraftTest.java`：未保存不落盘不联网、取消、独立开关持久化、预设复制不互相修改。
- 既有 `PreviewGeometryBoundsTest` 同步回归通过。

这是完整组件镜像，原动画中尾尖向左摆的部分会变为向右摆；父级头部和身体动作保持原样。贴图内画死的非对称光影也会随画面翻转，这是「纹理与造型同翻」的预期行为，不会重画用户原贴图。实际游戏中的审美、遮挡和操作体验仍需用户验收；本轮没有启动或完整构建游戏。
